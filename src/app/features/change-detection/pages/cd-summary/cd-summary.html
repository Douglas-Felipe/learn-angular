Como o Angular sabe o que atualizar na tela?

De um vigia que checa o prédio inteiro (Zone.js), passando por placas de "Não Perturbe" (OnPush), até sensores que apontam exatamente qual apartamento mudou (Signals): veja como o Angular evoluiu para atualizar apenas o necessário.

1. Zone.js (Angular Clássico) Estratégia padrão antiga: Eager como Default

O Porteiro Curioso que Bate em Todas as Portas

Imagine um prédio cheio de apartamentos (seus componentes). O Zone.js funcionava como um porteiro com ouvido super apurado: sempre que acontecia qualquer barulho no prédio — um clique de botão, um setTimeout ou uma resposta da API — ele sabia que algo tinha acontecido, mas não fazia ideia de em qual apartamento.

Passo 1 • Barulho

Um clique, timer ou resposta HTTP acontece em qualquer ponto da aplicação.

Passo 2 • Alarme geral

O Zone.js avisa o Angular: "Ei, algo rodou! Melhor checar se a tela mudou."

Passo 3 • Porta em porta

No modo Eager, o Angular bate em todas as portas do térreo à cobertura comparando tudo.

2. OnPush & Armadilhas Clássicas Por que a tela às vezes não atualizava

A Placa de "Não Perturbe" na Porta do Apartamento

Para evitar que o porteiro batesse em todo mundo à toa, o Angular criou o OnPush: cada componente pendura uma placa de "Não Perturbe". O Angular só entra nele quando recebe um aviso claro (um clique dentro dele, um novo valor de input(), async pipe ou markForCheck()). É daí que surgem os 3 erros mais comuns:

3. Zoneless + Signals (Angular Moderno) OnPush padrão no Angular v22

Notificação Direta por Assinatura (Entrega por GPS)

Com Signals, aposentamos o porteiro curioso (Zone.js). Em vez de ouvir barulhos genéricos no prédio, cada signal() funciona como uma lista de assinantes: ele sabe exatamente quais apartamentos exibem aquele valor na tela.

Sem "esquecer de avisar"

Mesmo dentro de setTimeout, WebSocket ou serviço compartilhado, chamar signal.update() notifica a tela automaticamente — sem precisar de markForCheck().

Pais apenas dão passagem

Os componentes ancestrais não têm seus templates reavaliados: eles só recebem um sinal de passagem (Traversal) até o destino.

Atualização cirúrgica

Apenas o componente que leu o signal é atualizado. Todo o resto da árvore fica intacto com 0 trabalho desperdiçado.
